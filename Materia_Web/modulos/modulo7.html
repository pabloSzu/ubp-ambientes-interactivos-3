🧩 CUDA

El lenguaje para hablar directamente con la GPU de NVIDIA. Escribís código que corre en miles de "threads" de GPU al mismo tiempo. Cada thread procesa un pedacito del problema.

Un kernel CUDA procesa 1000 elementos en paralelo: cada thread suma a[i] + b[i]. Los 1000 se ejecutan simultáneamente.
📡 MPI

Para cuando ni una GPU alcanza y necesitás 1000 computadoras conectadas en red. Cada máquina tiene su propia memoria y se comunican enviando mensajes explícitos.

HPC = muchas computadoras trabajando como una. La GPU hace miles de cálculos simples en paralelo. CUDA te da acceso directo a esa potencia. MPI conecta miles de máquinas en red. El cloud alquila todo esto sin comprarlo.

La ley que faltaba

Gustafson-Barsis vs Amdahl — el debate de los 40 años

Amdahl (1967) dice que el speedup está acotado. Gustafson (1988) dice que Amdahl se equivoca porque en HPC el problema crece con los cores — más poder = resolver un problema mayor en el mismo tiempo, no el mismo problema más rápido.

Ley de Amdahl 1967 — Problema de tamaño fijo
S(N) = 1 / ((1−P) + P/N)

El speedup converge a 1/(1-P) sin importar cuántos cores agregues. El cuello de botella serial es infranqueable.

⚠️ Pessimista: con 90% paralelo, el máximo speedup es ×10 — con ∞ cores.
VS
Ley de Gustafson-Barsis 1988 — Problema escalado
S(N) = N − (1−P)·(N−1)

Con más cores podés resolver un problema N veces mayor en el mismo tiempo. El speedup crece casi linealmente.

✅ Optimista: para HPC real, aumentar cores = escalar el problema, no solo acelerar.
Amdahl — speedup acotado
Speedup actual: ×1.0  ·  Techo teórico: ×5.0
Gustafson — escala con N
Speedup actual: ×1.0  ·  Crecimiento: lineal

¿Por qué 0.5µs vs 5µs importa tanto?

En una simulación MPI con 1000 nodos que se sincronizan 1000 veces por segundo: Ethernet agrega 5 segundos de overhead de red por segundo de cómputo. InfiniBand lo reduce a 0.5 segundos. Con una workload de 24 horas, eso son 108 horas de diferencia — más de 4 días extra solo por la red.

Java de alto rendimiento

Código HPC en Java

Java no es C++, pero con ForkJoin, BLAS bindings y cuidado del cache, se puede hacer HPC serio. Estos tres patrones son la base de cualquier cómputo de alto rendimiento en la JVM.

Multiplicación de matrices: el benchmark estándar de HPC. La versión secuencial es O(n³). Con ForkJoin y división por tiles aprovechamos la caché L1/L2 y paralelizamos filas. En producción se usa BLAS (OpenBLAS, MKL) que usa SIMD automáticamente.

import java.util.concurrent.*;

public class MatrizParalela {
    static final int UMBRAL = 64; // tile size para caché locality

    static class MultiplyTask extends RecursiveAction {
        final double[][] A, B, C;
        final int rowInicio, rowFin;

        MultiplyTask(double[][] A, double[][] B, double[][] C, int r0, int r1) {
            this.A = A; this.B = B; this.C = C;
            this.rowInicio = r0; this.rowFin = r1;
        }

        @Override
        protected void compute() {
            int rows = rowFin - rowInicio;
            if (rows <= UMBRAL) {
                // Kernel secuencial — acceso por filas para localidad de caché
                int n = B[0].length, p = B.length;
                for (int i = rowInicio; i < rowFin; i++) {
                    for (int k = 0; k < p; k++) {          // loop k antes de j
                        double aik = A[i][k];               // localidad de A[i]
                        for (int j = 0; j < n; j++) {
                            C[i][j] += aik * B[k][j];
                        }
                    }
                }
                return;
            }
            int mid = (rowInicio + rowFin) / 2;
            invokeAll(
                new MultiplyTask(A, B, C, rowInicio, mid),
                new MultiplyTask(A, B, C, mid, rowFin)
            );
        }
    }

    public static double[][] multiplicar(double[][] A, double[][] B) {
        int n = A.length;
        double[][] C = new double[n][B[0].length];
        ForkJoinPool.commonPool()
                    .invoke(new MultiplyTask(A, B, C, 0, n));
        return C;
    }

    public static void main(String[] args) {
        int N = 1024;
        double[][] A = new double[N][N];
        double[][] B = new double[N][N];
        // ... inicializar A y B

        long t0 = System.nanoTime();
        double[][] C = multiplicar(A, B);
        long ms = (System.nanoTime() - t0) / 1_000_000;
        System.out.println("1024×1024 paralela: " + ms + "ms");
        // Speedup esperado vs secuencial: ~Ncores ×
    }
}

Para operaciones uniformes sobre millones de elementos, .parallel() convierte la JVM en una mini-GPU: el ForkJoinPool distribuye el trabajo automáticamente en todos los cores. Es el equivalente Java al CUDA kernel más simple.

import java.util.stream.*;

public class GpuStyleJava {

    // Analogía a un CUDA kernel: la misma op aplicada a cada elemento en paralelo
    public static double[] aplicarFiltro(double[] pixeles, double factor) {
        // Un solo cambio: .parallel() → JVM usa todos los cores
        return DoubleStream.of(pixeles)
                .parallel()                           // GPU-style SIMD en CPU
                .map(p -> Math.min(1.0, p * factor))  // misma op en cada píxel
                .toArray();
    }

    // Suma de 100M elementos — benchmark clásico
    public static void benchmarkSuma() {
        int N = 100_000_000;
        double[] datos = new double[N];
        for (int i = 0; i < N; i++) datos[i] = i * 0.001;

        // Secuencial
        long t0 = System.nanoTime();
        double sumaSeq = 0;
        for (double d : datos) sumaSeq += d;
        long msSeq = (System.nanoTime() - t0) / 1_000_000;

        // Paralelo — distribuye en ForkJoinPool.commonPool() automáticamente
        t0 = System.nanoTime();
        double sumaPar = DoubleStream.of(datos).parallel().sum();
        long msPar = (System.nanoTime() - t0) / 1_000_000;

        System.out.printf("Secuencial: %dms%n", msSeq);
        System.out.printf("Paralelo:   %dms  (%.1f× speedup)%n",
                          msPar, (double) msSeq / Math.max(msPar, 1));
        System.out.println("Cores: " + Runtime.getRuntime().availableProcessors());
    }
}

MPI (Message Passing Interface) es el estándar de HPC en clusters. Cada proceso tiene su propia memoria y se comunica explícitamente. Este pseudocódigo en Java muestra el patrón scatter-compute-gather que usa Frontier para sus simulaciones.

// Patrón MPI conceptual en Java con ProcessBuilder / sockets
// En producción se usa la librería MPJ Express o la JNI sobre OpenMPI

public class MpiConceptual {
    // Proceso coordinador (rank 0)
    static void coordinador(int numWorkers, double[] datosGlobales) {
        int chunkSize = datosGlobales.length / numWorkers;

        // SCATTER: distribuir datos a cada worker
        for (int rank = 0; rank < numWorkers; rank++) {
            double[] chunk = Arrays.copyOfRange(
                datosGlobales, rank * chunkSize, (rank + 1) * chunkSize
            );
            enviarA(rank, chunk);   // MPI_Send
        }

        // GATHER: recolectar resultados parciales
        double resultadoTotal = 0;
        for (int rank = 0; rank < numWorkers; rank++) {
            resultadoTotal += recibirDe(rank);   // MPI_Recv
        }

        System.out.println("Resultado global: " + resultadoTotal);
    }

    // Proceso worker (rank 1..N)
    static void worker(int miRank) {
        double[] miChunk = recibirDelCoordinador();   // MPI_Recv

        // Cómputo local — sin comunicación con otros workers
        double resultado = 0;
        for (double v : miChunk) resultado += v * v;  // ejemplo: norma²

        enviarAlCoordinador(resultado);   // MPI_Send
    }
    // Este patrón scatter-compute-gather es la base de Hadoop MapReduce,
    // Spark, y cualquier framework de computación distribuida.
}

MatrizBenchmark.java — código para copiar y pegar 
import java.util.concurrent.*;
import java.util.Arrays;

public class MatrizBenchmark {
    static final int N = 512;
    static final int UMBRAL = 64;

    // ── Secuencial ────────────────────────────
    static double[][] multiplicarSeq(double[][] A, double[][] B) {
        int n = A.length, m = B[0].length, p = B.length;
        double[][] C = new double[n][m];
        for (int i = 0; i < n; i++)
            for (int k = 0; k < p; k++) {
                double aik = A[i][k];
                for (int j = 0; j < m; j++) C[i][j] += aik * B[k][j];
            }
        return C;
    }

    // ── Paralela con ForkJoin ─────────────────
    static class MultiTask extends RecursiveAction {
        double[][] A, B, C;
        int r0, r1;
        MultiTask(double[][] A, double[][] B, double[][] C, int r0, int r1) {
            this.A=A; this.B=B; this.C=C; this.r0=r0; this.r1=r1;
        }
        protected void compute() {
            if (r1 - r0 <= UMBRAL) {
                int m = B[0].length, p = B.length;
                for (int i = r0; i < r1; i++)
                    for (int k = 0; k < p; k++) {
                        double aik = A[i][k];
                        for (int j = 0; j < m; j++) C[i][j] += aik * B[k][j];
                    }
                return;
            }
            int mid = (r0 + r1) / 2;
            invokeAll(new MultiTask(A,B,C,r0,mid), new MultiTask(A,B,C,mid,r1));
        }
    }

    static double[][] multiplicarPar(double[][] A, double[][] B) {
        double[][] C = new double[A.length][B[0].length];
        ForkJoinPool.commonPool().invoke(new MultiTask(A, B, C, 0, A.length));
        return C;
    }

    public static void main(String[] args) {
        double[][] A = new double[N][N];
        double[][] B = new double[N][N];
        for (int i = 0; i < N; i++)
            for (int j = 0; j < N; j++) { A[i][j] = i+j; B[i][j] = i-j; }

        // ── Paso 1: medir secuencial ──────────
        long t0 = System.nanoTime();
        double[][] Cs = multiplicarSeq(A, B);
        long msSeq = (System.nanoTime() - t0) / 1_000_000;
        System.out.println("Secuencial: " + msSeq + "ms");

        // ── Paso 2: medir paralela ────────────
        t0 = System.nanoTime();
        double[][] Cp = multiplicarPar(A, B);
        long msPar = (System.nanoTime() - t0) / 1_000_000;
        System.out.println("Paralela:   " + msPar + "ms");

        // ── Paso 3: speedup ───────────────────
        System.out.printf("Speedup:    %.2f×%n", (double) msSeq / Math.max(msPar,1));
        System.out.println("Cores:      " + Runtime.getRuntime().availableProcessors());
        System.out.println("Correcto:   " + (Math.abs(Cs[1][1] - Cp[1][1]) < 0.001));
    }
}

Glosario — los términos que van a escuchar en producción

Tocá o hacé hover en cada tarjeta para ver la definición. 8 términos que distinguen a alguien que habla en serio de HPC de alguien que lo googlea.

FLOPS Tocá

Floating-Point Operations Per Second. La métrica universal de rendimiento HPC. 1 TFlop = 10¹² ops/seg. NVIDIA H100: 67 TFlops (FP32). Frontier: 1.1 ExaFlops (FP64).

VRAM Tocá

Video RAM — memoria dedicada de la GPU. El modelo ML debe caber entero en VRAM para inferencia eficiente. H100: 80GB HBM3 a 3.35 TB/s de ancho de banda.

CUDA Tocá

Compute Unified Device Architecture. Plataforma de NVIDIA para programar GPUs. Organiza threads en warps (32) → blocks → grids. El programador escribe un "kernel" que corre en miles de threads simultáneos.

Warp Tocá

Unidad de ejecución CUDA: 32 threads con la MISMA instrucción (SIMT). Si threads divergen dentro del warp (if/else), los idle esperan — "warp divergence" es el gran enemigo del rendimiento GPU.

MPI Tocá

Message Passing Interface. Estándar para clusters HPC. Cada proceso tiene su propia memoria y se comunica con MPI_Send/Recv explícitos. Todos los TOP500 lo usan. OpenMPI y MPICH son las implementaciones más comunes.

HBM Tocá

High Bandwidth Memory. Memoria 3D apilada sobre el chip GPU. H100 HBM3: 3.35 TB/s vs GDDR6 de 1 TB/s. El ancho de banda de memoria es el cuello de botella real en ML — no los FLOPS.

Spot Instance Tocá

Capacidad de cómputo no utilizada vendida con descuento 70–90%. AWS puede interrumpirla con 2 min de aviso. Ideal para ML training con checkpointing, render farms y batch jobs tolerantes a fallos.

NUMA Tocá

Non-Uniform Memory Access. En servidores multi-socket cada CPU tiene su RAM "local" (rápida) y puede acceder a la del otro socket (lenta, ~2× más latencia). Ignorar NUMA destruye el rendimiento en servidores de 2+ sockets.

Presentá tu análisis con: (1) qué hace el sistema, (2) cuál es el cuello de botella computacional, (3) qué arquitectura usa y por qué, (4) cómo escalaría si la demanda se multiplica ×10. Mínimo 1 diagrama propio.
