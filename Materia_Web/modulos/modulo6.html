🏗️ Paralelismo real

Secuencial: un albañil construye toda la casa solo. Paralelo: 10 albañiles, cada uno en una parte distinta, al mismo tiempo. La obra termina mucho más rápido.

IntStream.range(0,n).parallel().sum() usa todos los cores disponibles sin que hagas nada extra.
📐 Ley de Amdahl

Si el 20% de tu tarea es imprescindiblemente serial (configurar, combinar resultados), por más trabajadores que pongas, ese 20% siempre lo hace uno solo. El speedup máximo es ×5, sin importar cuántos cores tenés.

S = 1/(0.2 + 0.8/∞) = 5×. Con 100% paralela: speedup infinito. Con 20% serial: nunca más de 5×.
⚡ Speedup

La versión secuencial tarda 10 segundos. La paralela tarda 2.5 segundos. El speedup es ×4 (4 veces más rápido). Si tenés 8 cores y el speedup es ×4, la eficiencia es 50%.

Estás "desperdiciando" la mitad del hardware. El ideal es speedup ≈ cantidad de cores (speedup lineal).
🎯 SIMD

En vez de sumar 4 números de uno en uno, los sumás todos al mismo tiempo con una sola instrucción. El procesador tiene "carriles" paralelos para datos.

Las GPUs son SIMD extremo: miles de cores haciendo la misma operación sobre datos distintos simultáneamente.
🐌 Overhead

Crear un hilo cuesta tiempo. Dividir el trabajo cuesta tiempo. Juntar los resultados cuesta tiempo. Para sumar 5 números, el overhead es mayor que el beneficio.

ForkJoin tiene un UMBRAL: si el subproblema es menor que N elementos, resolverlo directo sin crear más hilos.

Paralelismo = dividir el trabajo entre múltiples cores. La Ley de Amdahl define el límite real (la parte serial manda). El speedup mide la mejora. El overhead es el costo de coordinar — para problemas pequeños destruye el beneficio.

El límite invisible

La Ley de Amdahl

Antes de agregar cores, calculá el límite. La ley de Amdahl (1967) revela algo contraintuitivo: el cuello de botella no es el hardware — es la fracción serial de tu código.

Con solo 1% de código serial, el máximo teórico es ×100 — independientemente de cuántos cores tengas.
El muro serial

Si el 30% de tu código es inevitablemente serial, el speedup máximo posible es ×3.3, sin importar si usás 8, 64 o 1000 cores.

Rendimientos decrecientes

El beneficio de agregar el core número N+1 siempre es menor que el core N. La curva de speedup se aplana inevitablemente.

Primero optimizá el serial

Reducir la parte serial de 30% a 10% triplica el speedup posible. Es más efectivo que triplicar los cores.

Tres formas de paralelizar

Java ofrece niveles de abstracción para el paralelismo: desde Parallel Streams (una palabra) hasta ForkJoin manual con control total. Elegí según la complejidad del problema.

Usá .parallel() cuando el trabajo es sobre colecciones o streams y no necesitás control fino. Es un único cambio en el código — Java elige automáticamente los threads usando el ForkJoinPool.commonPool().

import java.util.stream.LongStream;

public class SumaParallelStream {
    public static void main(String[] args) {
        long N = 10_000_000L;

        // Secuencial
        long t0 = System.currentTimeMillis();
        long seq = LongStream.rangeClosed(1, N).sum();
        long tSeq = System.currentTimeMillis() - t0;

        // Paralelo — un solo cambio: .parallel()
        t0 = System.currentTimeMillis();
        long par = LongStream.rangeClosed(1, N).parallel().sum();
        long tPar = System.currentTimeMillis() - t0;

        System.out.println("Secuencial: " + seq + " en " + tSeq + "ms");
        System.out.println("Paralelo:   " + par + " en " + tPar + "ms");
        System.out.printf("Speedup: %.2fx%n", (double) tSeq / Math.max(tPar, 1));
    }
}

Usá RecursiveTask<V> para divide-y-vencerás con resultado. El patrón es: si el problema es pequeño, resolverlo directo. Si no, dividirlo, hacer fork() en uno y compute() + join() en el otro. Work-stealing automático.

import java.util.concurrent.RecursiveTask;
import java.util.concurrent.ForkJoinPool;

public class SumaRecursiva {
    static final int UMBRAL = 10_000; // tamaño mínimo de chunk

    static class SumTask extends RecursiveTask<Long> {
        final long[] arr;
        final int desde, hasta;

        SumTask(long[] arr, int desde, int hasta) {
            this.arr = arr; this.desde = desde; this.hasta = hasta;
        }

        @Override
        protected Long compute() {
            if (hasta - desde <= UMBRAL) {
                // Caso base: sumar directo (sin más división)
                long sum = 0;
                for (int i = desde; i < hasta; i++) sum += arr[i];
                return sum;
            }
            int mid = (desde + hasta) / 2;
            SumTask izq = new SumTask(arr, desde, mid);
            SumTask der = new SumTask(arr, mid, hasta);

            izq.fork();                         // lanza izq en otro thread del pool
            return der.compute() + izq.join();  // der en este thread + espera izq
        }
    }

    public static void main(String[] args) {
        int N = 1_000_000;
        long[] arr = new long[N];
        for (int i = 0; i < N; i++) arr[i] = i + 1L;

        long t0 = System.currentTimeMillis();
        long result = ForkJoinPool.commonPool().invoke(new SumTask(arr, 0, N));
        long t = System.currentTimeMillis() - t0;

        System.out.println("Suma: " + result + " en " + t + "ms");
        System.out.println("Cores: " + Runtime.getRuntime().availableProcessors());
    }
}

Usá RecursiveAction (sin valor de retorno) para operaciones in-place. invokeAll() es más limpio que fork+join manual cuando dividís en exactamente dos subtareas del mismo tipo.

import java.util.concurrent.*;
import java.util.Arrays;

public class MergesortParalelo {
    static final int UMBRAL = 5_000;

    static class SortTask extends RecursiveAction {
        final int[] arr;
        final int desde, hasta;

        SortTask(int[] arr, int desde, int hasta) {
            this.arr = arr; this.desde = desde; this.hasta = hasta;
        }

        @Override
        protected void compute() {
            if (hasta - desde <= UMBRAL) {
                Arrays.sort(arr, desde, hasta); // caso base: sort secuencial
                return;
            }
            int mid = (desde + hasta) / 2;
            // invokeAll lanza ambas subtareas y espera a que terminen
            invokeAll(
                new SortTask(arr, desde, mid),
                new SortTask(arr, mid,   hasta)
            );
            merge(arr, desde, mid, hasta);
        }
    }

    static void merge(int[] a, int l, int m, int r) {
        int[] tmp = Arrays.copyOfRange(a, l, m);
        int i = 0, j = m, k = l;
        while (i < tmp.length && j < r)
            a[k++] = tmp[i] <= a[j] ? tmp[i++] : a[j++];
        while (i < tmp.length) a[k++] = tmp[i++];
    }

    public static void main(String[] args) {
        int N = 500_000;
        int[] arr = new int[N];
        for (int i = 0; i < N; i++) arr[i] = N - i; // invertido = peor caso

        long t0 = System.currentTimeMillis();
        ForkJoinPool.commonPool().invoke(new SortTask(arr, 0, N));
        System.out.println("Ordenado en: " + (System.currentTimeMillis() - t0) + "ms");
        System.out.println("Primeros 5: " + Arrays.toString(Arrays.copyOf(arr, 5)));
    }
}

Paralelismo en TV y Streaming

Los sistemas de streaming y TV interactiva son uno de los ejemplos más ricos de paralelismo en producción. Todo lo que aprendiste en este módulo está corriendo ahora mismo en los servidores de Netflix, YouTube y en los STBs de IPTV.

SIMD + MIMD
Netflix — Encoding multi-resolución

Cada video se convierte a 15 resoluciones (240p–4K) simultáneamente. La GPU aplica SIMD para procesar miles de píxeles en paralelo, mientras que decenas de instancias MIMD manejan distintos videos al mismo tiempo.

×15 resoluciones en paralelo por video
Paralelismo de datos
YouTube — Generación de thumbnails

Cuando subís un video, YouTube extrae frames en posiciones específicas y los procesa en paralelo para generar las miniaturas. Es un caso de embarassingly parallel: cada frame es independiente, speedup casi lineal.

~60 thumbnails por video, todos a la vez
MIMD — Memoria compartida
IPTV / Ginga — Múltiples streams

Un STB (Set-Top Box) de IPTV maneja simultáneamente el stream de video principal, las aplicaciones Ginga interactivas, la guía de programación EPG y el canal de datos. Cada proceso corre en su propio hilo con memoria compartida.

4+ hilos concurrentes en un STB moderno
Memoria distribuida
CDN — Contenido en el borde

Una CDN (Content Delivery Network) distribuye el contenido en cientos de servidores geográficamente separados. Es memoria distribuida pura: cada nodo tiene su propia caché, se coordinan por mensajes HTTP, y el usuario recibe el frame del nodo más cercano.

<20ms latencia al nodo CDN más cercano

import java.util.concurrent.*;
import java.util.stream.LongStream;

public class SumaParalela {
    static final int UMBRAL = 50_000;

    static class SumTask extends RecursiveTask<Long> {
        final long[] arr;
        final int desde, hasta;

        SumTask(long[] arr, int desde, int hasta) {
            this.arr = arr; this.desde = desde; this.hasta = hasta;
        }

        @Override
        protected Long compute() {
            if (hasta - desde <= UMBRAL) {
                long sum = 0;
                for (int i = desde; i < hasta; i++) sum += arr[i];
                return sum;
            }
            int mid = (desde + hasta) / 2;
            SumTask izq = new SumTask(arr, desde, mid);
            SumTask der = new SumTask(arr, mid, hasta);
            izq.fork();
            return der.compute() + izq.join();
        }
    }

    public static void main(String[] args) {
        int N = 1_000_000;
        long[] arr = new long[N];
        for (int i = 0; i < N; i++) arr[i] = i + 1L;
        long esperado = (long) N * (N + 1) / 2;

        // 1. Secuencial
        long t0 = System.currentTimeMillis();
        long sumSeq = 0;
        for (long x : arr) sumSeq += x;
        long tSeq = System.currentTimeMillis() - t0;

        // 2. ForkJoin
        t0 = System.currentTimeMillis();
        long sumFJ = ForkJoinPool.commonPool().invoke(new SumTask(arr, 0, N));
        long tFJ = System.currentTimeMillis() - t0;

        // 3. Parallel Stream
        t0 = System.currentTimeMillis();
        long sumPS = LongStream.of(arr).parallel().sum();
        long tPS = System.currentTimeMillis() - t0;

        System.out.println("Esperado:         " + esperado);
        System.out.println("Secuencial:       " + sumSeq + " (" + tSeq + "ms)");
        System.out.println("ForkJoin:         " + sumFJ + " (" + tFJ + "ms)");
        System.out.println("ParallelStream:   " + sumPS + " (" + tPS + "ms)");
        System.out.println("Cores disponibles: " + Runtime.getRuntime().availableProcessors());
        if (tSeq > 0)
            System.out.printf("Speedup FJ: %.2fx%n", (double) tSeq / Math.max(tFJ, 1));
    }
}

Glosario

Glosario

Tocá o hacé hover en cada tarjeta para ver la definición. Estos son los términos que van a aparecer en parciales, entrevistas y en producción.

Ley de Amdahl Tocá

S(N) = 1/((1−P) + P/N). Define el speedup máximo teórico cuando se paraleliza la fracción P de un programa usando N cores. La parte serial (1−P) es el límite infranqueable — con P=90% y ∞ cores, máximo ×10.

SIMD Tocá

Single Instruction Multiple Data. La misma operación se aplica simultáneamente a múltiples datos. Modelo de GPUs e instrucciones vectoriales (AVX, NEON). Ideal para álgebra lineal y procesamiento de imágenes.

MIMD Tocá

Multiple Instructions Multiple Data. Múltiples cores ejecutan instrucciones distintas sobre datos distintos de forma independiente. Modelo de los servidores multicore modernos y clusters HPC.

Speedup Tocá

Factor de mejora de rendimiento: S = T_secuencial / T_paralelo. Un speedup de ×3 significa que la versión paralela tarda 3 veces menos. El speedup ideal (= N cores) se llama speedup lineal.

ForkJoinPool Tocá

Pool de threads de Java optimizado para tareas divide-y-vencerás. Usa work-stealing: un thread inactivo "roba" tareas de la cola de otro ocupado. ForkJoinPool.commonPool() retorna el pool compartido de la JVM.

RecursiveTask Tocá

Clase abstracta de Java (java.util.concurrent) para tareas ForkJoin que retornan un valor. En compute(): si el problema es pequeño resolverlo directo; si no, dividir en subtareas, fork() una y join() la otra.

Overhead Tocá

Costo adicional de crear, coordinar y sincronizar threads. Para tareas muy pequeñas el overhead supera el beneficio. El UMBRAL en ForkJoin define el tamaño mínimo donde paralelizar vale la pena.

Eficiencia Tocá

E = Speedup / N. Mide qué fracción de los cores se aprovecha realmente. Con 8 cores y speedup ×4, la eficiencia es 50%. Eficiencia baja indica que el overhead o la parte serial dominan el tiempo.
