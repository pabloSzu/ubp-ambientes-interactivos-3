El concepto clave

Interfaces y modelos mentales

El diseño empieza en papel

Una interfaz no es una pantalla — es un contrato implícito entre el sistema y la persona que lo usa. Ese contrato dice: "si hacés esto, va a pasar aquello". Cuando el contrato se rompe, la experiencia falla.

El concepto clave es el modelo mental: la representación interna que el usuario construye de cómo funciona el sistema. Si la interfaz no coincide con ese modelo, el usuario se pierde, se frustra y abandona.

El trabajo del diseñador de interfaces no es hacer algo bonito — es hacer que el sistema y el modelo mental del usuario se alineen perfectamente.

¿Sabías esto?

Los usuarios forman su primera impresión de una interfaz en solo 50 milisegundos. Antes de leer una sola palabra, ya decidieron si confían en ese sistema o no.

Diseño visual

Los tres pilares de la jerarquía visual

Antes de evaluar una interfaz, hay que entender cómo el ojo humano lee una pantalla. Estos tres principios determinan todo.

01

Tipografía y peso

El tamaño y el peso tipográfico crean orden de lectura. El ojo sigue jerarquías: H1 → H2 → body. Una interfaz sin jerarquía tipográfica es ruido visual.

Tamaño · Peso · Contraste
02

Color y contraste

El color guía la atención, comunica estado y crea grupos visuales. El contraste asegura legibilidad. Sin suficiente contraste, la interfaz excluye a millones de usuarios.

Atención · Estado · Accesibilidad
03

Espacio y Gestalt

El espacio en blanco no es vacío — es separación intencional. La Gestalt explica cómo el cerebro agrupa elementos: proximidad, similitud y continuidad.

Vocabulario técnico

Glosario

Tocá cada tarjeta para ver la definición. Estos términos son el lenguaje profesional del diseño de interfaces.

Interfaz Tocá

Punto de contacto entre un sistema y sus usuarios. No es solo la pantalla — es el conjunto de elementos, reglas y comportamientos que median la interacción.

Affordance Tocá

Propiedad de un objeto que sugiere cómo puede ser usado. Un botón elevado sugiere que se puede presionar. Acuñado por Don Norman en "The Design of Everyday Things".

Signifier Tocá

Señal perceptible que comunica al usuario qué acción es posible. Diferencia de affordance: el affordance existe aunque no se vea; el signifier es explícito y visible.

Usabilidad Tocá

Medida en que un sistema puede ser usado por usuarios específicos para lograr objetivos específicos con efectividad, eficiencia y satisfacción. ISO 9241-11.

Heurística Tocá

Regla general o principio para la evaluación de usabilidad. Las 10 heurísticas de Nielsen son el estándar de la industria para auditar interfaces sin necesidad de test con usuarios.

Flujo de usuario Tocá

Secuencia de pasos que un usuario sigue para completar una tarea dentro de un sistema. Visualizar el flujo permite detectar fricciones, pasos innecesarios y puntos de abandono.

Accesibilidad Tocá

Grado en que un sistema puede ser usado por personas con diversas capacidades físicas, cognitivas o sensoriales. WCAG define los estándares internacionales de accesibilidad web.

Consistencia Tocá

Principio de diseño que establece que los mismos elementos deben comportarse y verse igual en toda la interfaz. Reduce la carga cognitiva del usuario y genera confianza.

Tu turno

Actividad — Auditoría de Interfaz

Esta actividad vale 10 puntos. Vas a aplicar las heurísticas de Nielsen como herramienta real de evaluación sobre una interfaz que ya conocés.

Antes de arrancar

¿Cómo se hace una auditoría de UX?

Una auditoría de interfaz no es opinar sobre si algo "se ve bien". Es evaluar sistemáticamente con criterios técnicos. Las heurísticas de Nielsen son tu lente: cada pantalla la mirás preguntando "¿qué heurística respeta? ¿cuál viola?".

La clave es ser específico. "La app es confusa" no es una auditoría. "El botón de confirmar no da feedback visual tras el click, violando H1 — Visibilidad del estado" sí lo es. La diferencia es la diferencia entre intuición y criterio profesional.

Elegí pantallas donde pasan cosas: login, formularios, confirmaciones, errores
Por cada violación: nombrá la heurística, describí el problema y proponé la solución
La propuesta de mejora puede ser un sketch a mano, no necesitás Figma
Ejemplo de ficha de auditoría
WhatsApp Web
Pantalla analizada: envío de archivo
Heurística respetada · H1
La barra de progreso muestra el avance del envío en tiempo real
Heurística violada · H5
No hay límite de tamaño visible antes de intentar enviar el archivo
Propuesta de mejora
Mostrar "Máximo 2GB" en el selector de archivos, antes de que el usuario elija
Misión 02

Auditá una interfaz real

Paso 1 — Elegí tu app

Seleccioná una aplicación o sitio web que usés regularmente. Puede ser una app móvil, un servicio web, una plataforma educativa o un sistema institucional. Tiene que ser algo que conozcas bien.

Paso 2 — Capturá 3 pantallas clave

Elegí 3 pantallas donde pasan cosas: una pantalla de login o registro, un formulario o flujo de pago, una pantalla de error o confirmación. Captura de pantalla o foto está perfecto.

Paso 3 — Aplicá las heurísticas

Por cada pantalla: identificá al menos 2 heurísticas que se respetan y 1 que se viola. Nombrá la heurística, describí el problema con precisión y explicá por qué es un problema.

Paso 4 — Proponé mejoras

Para cada violación encontrada, proponé una mejora concreta. Puede ser un sketch a mano, una descripción detallada del cambio o un mockup en Figma/cualquier herramienta. Lo importante es la especificidad.

Paso 5 — Armá tu Ficha de Auditoría

Reuní todo en un documento: capturas, análisis heurístico (respetadas + violadas), propuestas de mejora. Formato libre: PDF, Notion, slides o Figma. Subilo al Campus Virtual antes de la próxima clase.
