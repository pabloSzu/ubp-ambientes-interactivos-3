Antes de tocar botones

Explicado bien simple

Si nunca programaste concurrencia, empezá por acá. La idea no es sonar técnico: es entender la película.

1

Un hilo es un trabajador

Tu programa es una cocina. Un hilo es una persona haciendo una tarea. Varios hilos pueden trabajar durante el mismo tiempo.

2

El recurso compartido es la mesa

Si todos usan la misma mesa sin reglas, se pisan. En código, esa mesa puede ser una variable, lista, celda o cola.

3

Una carrera es decidir tarde

Dos hilos ven una celda libre al mismo tiempo. Ambos creen que pueden entrar. Cuando llegan, chocan.

4

Un lock es pedir permiso

El lock hace que revisar y ocupar el recurso ocurra sin interrupciones. Evita choques, pero puede generar espera.

Simulador interactivo

Agentes que chocan

Cada agente intenta ocupar celdas de una memoria compartida. En modo sin sincronizacion, dos agentes pueden elegir el mismo destino. En modo con lock, el acceso se coordina y las colisiones bajan.

Que estas viendo

En modo sin lock, cada agente decide a la vez. Si dos eligen la misma celda, aparece una colision.

Lo que tienen que llevarse

Proceso vs hilo

Un proceso tiene memoria propia. Un hilo vive dentro de un proceso y comparte memoria con otros hilos. Esa memoria compartida hace que la comunicacion sea rapida, pero tambien peligrosa.

Race condition

Hay condicion de carrera cuando el resultado depende del orden de ejecucion. Si el orden cambia entre corridas, el bug aparece y desaparece como si fuera aleatorio.

Java mental model

Thread.start() lanza una ejecucion concurrente. join() espera. sleep() pausa. La sincronizacion define quien puede tocar un recurso compartido.

La historia de un tick

  1. El scheduler da turno. Cada hilo intenta avanzar.
  2. El hilo mira el recurso. Pregunta si una celda parece libre.
  3. Sin lock: otro hilo puede mirar lo mismo antes de que el primero escriba.
  4. Con lock: revisar y ocupar se vuelven una operación protegida.
  5. Resultado: menos choques, pero algunos hilos esperan.

Actividad evaluable

Choque de agentes concurrentes

Implementar en Java una simulacion con al menos 10 agentes ejecutados como hilos. Primero debe observarse el problema sin sincronizacion. Luego se debe proponer una estrategia para reducir o eliminar colisiones.

  1. Crear una grilla compartida y agentes que intenten moverse.
  2. Ejecutar 5 corridas sin sincronizacion y registrar resultados.
  3. Explicar por que el resultado no es determinista.
  4. Agregar una solucion con synchronized, Lock o control equivalente.
  5. Entregar codigo, capturas, tabla de colisiones y conclusion.
